# Go back to the list

An item page opened from a list on the served Desk shows two links at the top
and again at the bottom of the page. They sit at the bottom as well so you can
reach them with your thumb after you answer or reply.

**Back to** and the list's name returns you to the list you came from. The
link opens the same tab, with the same project and topic in Conversations, or
the same project, tag and search in Hold, and brings the item's row into view. The lists are the Desk tabs **Needs you**,
**Conversations** and **Archived**, the **Watch** page, and the Hold tabs
**References**, **Answered** and **Hold conversations**.

**Next unread** opens the next unread item in the same list, after the one you
are reading. When you reach the end of the list it continues from the start.
The link is missing when no other item in the list is unread.

- In **Needs you**, every item in the list counts, because each one needs you.
  Catch-up notices do not count. The link opens the first unread reply, or the
  first open question.
- In every other list, an item is unread when it has an
  [Unread reply](../reference/glossary.md#status-words).
- In **Conversations**, **Next unread** follows the Desk's project and topic,
  as Hold follows its filters.
- In Hold, **Next unread** follows the project, tag and search of the list you
  came from.

Answering, sending a message or marking a reply read keeps you on the page.
Select **Next unread** when you are ready. An answered question set has left
**Needs you**, yet **Next unread** still continues from where it stood.

If you open an item page without a list, for example from a bookmark or a
pasted address, the link reads **Back to Desk** and there is no **Next unread**.

The list is part of the page's address, as `from=` followed by the list's name.
Quarterdeck stores nothing about where you have been.
